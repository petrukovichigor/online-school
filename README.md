# 📚 Online School: учебное IT-приложение «Онлайн-школа»

Десктопное приложение для онлайн-школы с курсами по программированию, иностранным языкам, дизайну, маркетингу и бизнесу. В приложении две роли: **Студент** и **Преподаватель**, у каждой свой интерфейс и свои права доступа.

Студент выбирает курс в каталоге, оплачивает его, смотрит видеоуроки на YouTube и сдаёт домашние задания файлом. Преподаватель ведёт свои курсы, добавляет уроки и задания, проверяет работы и ставит оценки.

Данные хранятся в PostgreSQL, интерфейс собран по прототипам из Figma.

## 🗄 Структура базы данных

9 таблиц, все первичные ключи `SERIAL`.

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `students` | Студенты | email (уникальный), password_hash, phone_number |
| `teachers` | Преподаватели | email (уникальный), password_hash, salary |
| `categories` | Категории курсов | name (уникальное) |
| `courses` | Курсы | title, description, price, category_id, teacher_id |
| `lessons` | Уроки курса | position (порядок), title, video_url (YouTube) |
| `homeworks` | Домашние задания к уроку | lesson_id, description |
| `course_subscriptions` | Подписка студента на курс | student_id, course_id, status |
| `payments` | Оплата подписки | subscr_id (1:1), amount, status, transaction_id |
| `homework_submissions` | Сданные работы | homework_id, student_id, file_url, grade |

**Связи:**

* `categories`, `teachers` → `courses` (1:N)
* `courses` → `lessons` → `homeworks` (1:N)
* `students` + `courses` → `course_subscriptions` (M:N через подписку)
* `course_subscriptions` → `payments` (1:1)
* `students` + `homeworks` → `homework_submissions` (M:N через сдачу)

**Ограничения:**

* один студент не может подписаться на один курс дважды: `UNIQUE(student_id, course_id)`;
* одно задание сдаётся одним студентом один раз: `UNIQUE(homework_id, student_id)`;
* у подписки ровно один платёж: `UNIQUE(subscr_id)` в `payments`;
* `transaction_id` уникален, пустой, пока оплата не прошла.

## ⚙️ Бизнес-логика

### Оплата и доступ: «сначала оплата, потом доступ»

| Событие | `course_subscriptions.status` | `payments.status` | Доступ к урокам |
|---|---|---|---|
| Нажата кнопка «Купить» | `pending` | `pending` | нет |
| Оплата прошла | `active` | `paid` | да |
| Возврат денег | `cancelled` | `refunded` | нет |

* Сумма платежа равна цене курса на момент покупки.
* При повторной попытке оплаты обновляется тот же платёж, новый не создаётся.

### Уроки

* Урок принадлежит одному курсу, порядок задаёт `position`.
* Видео хранится ссылкой на YouTube.
* Уроки видны только при подписке со статусом `active`.

### Домашние задания

* К уроку может быть одно или несколько заданий.
* Студент сдаёт работу файлом, в базе хранится ссылка `file_url` (Google Drive).
* `grade` пустой (`NULL`), пока преподаватель не проверил работу. Шкала оценок 1–10.

### Безопасность

* Пароли хешируются `bcrypt` в Python, в базе лежит только хеш (60 символов).
* Логин и пароль от БД хранятся в `.env`, файл не попадает в Git.
* Все SQL-запросы параметризованы через `psycopg`, без склейки строк.

## 👤 User Flow

### Студент

1. Регистрация или вход по email и паролю.
2. Главная: категории и карточки курсов.
3. Категория → список курсов с ценой и преподавателем.
4. Страница курса → «Купить» → подписка и платёж в статусе `pending`.
5. Оплата успешна → подписка `active` → курс появляется в «Мои курсы».
6. Курс → уроки по порядку → видео на YouTube.
7. Задание к уроку → ссылка на файл → работа отправлена.
8. После проверки видна оценка.

### Преподаватель

1. Вход по email и паролю.
2. Список своих курсов с количеством активных студентов.
3. Курс → таблица студентов.
4. Добавление урока: название, порядок, ссылка на YouTube.
5. Добавление домашнего задания к уроку.
6. Сданные работы → открыть файл → поставить оценку.

## 🚀 Развёртывание базы

```bash
createdb online_school
psql -d online_school -f database/schema.sql   # структура таблиц
psql -d online_school -f database/seed.sql     # тестовые данные
```

В DBeaver: открыть файл в редакторе SQL подключения `online_school` и выполнить как скрипт (Alt+X). Сначала `schema.sql`, потом `seed.sql`.

`seed.sql` выполняется одной транзакцией и в конце сдвигает счётчики `SERIAL`, так что новые записи после сида получают корректные id.

Пример `.env`:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=online_school
DB_USER=postgres
DB_PASSWORD=your_password
```
